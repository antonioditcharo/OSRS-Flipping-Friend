# Durable maintenance delivery

20 October 2026. Read HANDOFF and the private consolidated delivery receipt for actual installation.

A displayed cancellation/replacement promise now needs a successful durable continuation commit.
Exact offer episode, account, side, quantity and managed-cost requirement are checked before the
client records or notifies the accepted instruction. A refused write withdraws the action and
queued numeric assistance; the existing offer stays working. Ordinary failed maintenance backs
off for that exact episode for 30 seconds so unrelated exits/entries can proceed. Fresh stops and
explicit wind-down retain priority. This retry delay never expires or deletes a continuation.

Continuation documents retain format 2 and legacy reads. Writes force the complete temporary file
before atomic replacement; unsupported atomic moves fail closed rather than deleting/replacing the
last committed file non-atomically. An interrupted temporary file is never promoted as evidence.
Dirty observed progress/removals retry even after temporary settled evidence is pruned, and remain
account-scoped in memory across profile switches. Unsaved collected hints cannot request a new
replacement; their partial holding protection remains. Unknown personal acquisition cost stays unknown.
A changed, unreadable, removed, foreign or future document is not overwritten from a cached book.
External replacement/rollback while loaded is a conflict, not an instruction to erase a promise.

Final authority refusal additionally withdraws the matching foreground trade before a successor is
applied. The real walkthrough cannot leave a declined sell actionable behind its editor queue.
Unrelated personal quotes and newer offer episodes survive a scoped withdrawal. Unsupported source
and expired queued-order guards can explicitly withdraw all advice, including an in-progress sell.
Delivered timing logs name the actual visible action after acceptance/withdrawal. Tests use their own console-only logger; synthetic trades/timings cannot enter the player log. Live timing receipts select the actual Client thread.

These are local workflow hints, never financial recovery or order authority. Final cash/eight-slot,
source, exact cost/tax, stock, risk and buy-limit checks still apply. No financial history, learning
binding, risk anchor, database schema or previous unknown is rewritten. Persistent storage failure
can still prevent that workflow; retries do not guarantee survival of progress that never committed
before power loss. Other account records and trading remain independently guarded.

Verification uses real disposable file failures, actual tracker callbacks, account switches/restarts,
legacy receipts and the real mid-entry walkthrough. Live cancel/collect/replace/relist and sustained
timings require player actions; source tests and installation do not establish full parity.
