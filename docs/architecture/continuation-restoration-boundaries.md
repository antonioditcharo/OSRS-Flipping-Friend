# Continuations across restoration and cancellation acceptance

21 October 2026. Read HANDOFF's delivery receipt for source, verification, merge, installation and
player acceptance. These are separate states. This batch prevents two reproduced plan-loss paths.

Collection checkpoints can commit before the ordinary offer snapshot. A crash or failed later
snapshot write can leave a durable collected remainder beside an older active offer with fewer
fills. Previously, an unrelated slot's first callback compared that cached counter with the saved
collection and permanently removed the continuation as a regression.

Continuation decisions now consume copied observations processed in the current login generation.
Persisted offers remain recovery/accounting records. Startup, shutdown, login, reconnect and hopping
reset the continuation observation set independently of loading a file; a same-profile load can
legitimately return early. Observations carry their account owner so a profile change cannot use
another account's still-loaded board to remove a hint.

EMPTY has no fill counters. It can create a continuation collection receipt only after a matching
nonempty predecessor processed in that generation. An untouched cached cancellation cannot become
fresh collection evidence. An already committed collection remains available for fresh revalidation
when cached evidence is absent; current canonical source, physical quantity, pricing and final
authority still govern any resulting order. Fresh regressions, completions and replacement episodes
retain their existing refusal/closure behavior. Cached sales alone cannot retire a rebuy promise;
fresh observed sales or separately proven canonical sale dispositions retain that role.

BUY cancellation proposals also used to clear accepted replacement hints while the worker merely
considered an exhausted limit, overdue order or unprofitable chase. These proposals now preserve the
promise. Only the presented, accepted cancellation retires it, with a forced durable commit before
guidance proceeds. Every cancellation carries its exact offer identity. Acceptance checks the active
BUY episode, slot, item, standing price and current remainder. A delayed card cannot retire a newer
same-item episode, and changed fills or failed writes withdraw guidance and preserve committed bytes.
Explicit owner choices such as sell-only and item rejection retain their existing separate behavior.

Regressions use disposable files and actual tracker callbacks: saved collection with stale active
snapshots, unrelated first callbacks, cached terminal/EMPTY, current terminal/late fills, genuine
counter regression, reconnect and account switches, cancellation proposals versus acceptance,
same-item slot reuse, changed price/quantity/state and failed atomic writes. Existing exact costs,
original acquisition plans, canonical dispositions, outbox identities and financial/risk guards stay
in force. Sale policy remains `companion-sale-5`; replay remains `account-replay-12` because this
changes client observation/acceptance boundaries, not simulated pricing or final sale policy.

No historical row or missing plan is repaired. Full-loop player acceptance, sustained latency,
qualified production replay, superior returns and validated forecasting remain open.
